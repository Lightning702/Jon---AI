# Jon — Demofilm

Der offizielle Produktfilm für **Jon 4.36.4** (FelWorks, getjon.info).
Jedes Bild entsteht zur Laufzeit im Browser aus HTML, CSS und SVG, jeder Ton
aus Oszillatoren. Kein Stock-Material, keine Fremdbilder, keine Musiklizenz.

| | Hauptfassung | Kurzfassung |
|---|---|---|
| Datei | `jon-demo-90s-1920x1080.mp4` | `jon-demo-20s-1080x1920.mp4` |
| Format | 1920 × 1080, 60 fps, H.264 | 1080 × 1920 (9:16), 60 fps, H.264 |
| Länge | exakt 90,000 s | exakt 20,000 s |
| Ton | Musik + Geräusche + Sprecher (de) | Musik + Geräusche, kein Sprecher |
| Untertitel | eingebrannt, deutsch | keine — Text steht gross im Bild |

Beide Fassungen sind ohne Ton verständlich: alles Wichtige steht als Text im Bild.

## 2. Shotlist — so wird jede Einstellung in der echten App nachgestellt

Vorbereitung für alle Aufnahmen: dunkles Design, Fenster auf 1920 × 1080
skaliert, Aufnahme mit 60 fps, Mauszeiger sichtbar, Benachrichtigungen aus.

| # | Einstellung | Klickpfad in Jon |
|---|---|---|
| 1 | Mini Jon auf dem Desktop | Kopfzeile → Schalter **🙂 Mini Jon** (oder **Strg+Alt+K**). Mini Jon mit der Maus nach unten rechts über die Taskleiste ziehen. Sprechblase entsteht beim Tagesbriefing bzw. auf Zuruf. |
| 3 | Downloads aufräumen | **Win+E** → `C:\Users\<Name>\Downloads`, Fenster links ablegen. Jon rechts daneben. Im Eingabefeld (`Frag Jon...`) die Nachricht tippen und senden. Beim Werkzeug „Dateien verschieben" erscheint der Freigabe-Dialog **„Jon möchte etwas ausführen"** → **Erlauben** klicken. Explorer im Hintergrund mitlaufen lassen. |
| 4 | Websuche mit Datum | Nur die Frage ins Eingabefeld tippen. Die Websuche startet selbst; alternativ `/suche`. Die Werkzeugzeile und die Quellzeile stehen automatisch in der Antwort. |
| 5 | Bild im Chat | Bildwunsch direkt ins Eingabefeld tippen. (Grosse Bildwerkstatt: Werkzeug-Menü → **🎨 Video / Foto**, Kürzel `/bild`.) Die drei Knöpfe stehen unter dem fertigen Bild. |
| 6 | Jon Code | Werkzeug-Menü in der Kopfzeile → **`</>` Jon Code** → Projektordner `C:\Projekte\landing` öffnen → `index.html` wählen → Anweisung im rechten Feld senden. Vorschau daneben aufziehen. |
| 7 | Handy koppeln | **Zahnrad** → **Diagnose & Handy koppeln**. QR-Code und Adresse stehen dort. Auf dem Handy `getjon.info/app` im Browser öffnen bzw. QR scannen. **Wichtig:** Adresse und Geräte-Schlüssel im Schnitt unkenntlich machen. |
| 8 | Freunde-Chat | Werkzeug-Menü → **💬 Freunde-Chat**. Für die zweite Bildhälfte einen zweiten PC (oder zweite Instanz) mit Annas Profil aufnehmen. |
| 9 | Spiele | Ins Eingabefeld `/spiele` tippen — die Befehlsliste zeigt **🕹️ /spiele · Alle Spiele**. Kachel **Blockwelt** anklicken. |
| 10 | Mini Jon gross | **Strg+Alt+K**. Farbe und Haustier: Kopfzeile → **🎨** neben dem Mini-Jon-Schalter (**Mini Jon anpassen**) → Farbe auf Rosa und zurück auf Gold, Begleiter **🐱 Katze** („Minka"). |

## 4. Neu bauen

```bash
python ton.py
node render.mjs --dauer=90 --ton=bau/ton-lang.wav --ziel=jon-demo-90s-1920x1080.mp4
node render.mjs --breite=1080 --hoehe=1920 --dauer=20 --ton=bau/ton-kurz.wav --ziel=jon-demo-20s-1080x1920.mp4
```

`ton.py` erzeugt Musik, Geräusche und die Sprecherspur (Windows-Stimme
„Microsoft Stefan", danach tiefer gestimmt und entzerrt) und schreibt die
Untertitelzeiten nach `js/vo.js`. `render.mjs` fährt Chrome ohne Fenster,
springt Bild für Bild durch `window.__seek(t)` und schiebt jedes Bild direkt
in ffmpeg — dadurch ist die Bildrate exakt, egal wie schnell der Rechner ist.

Einzelbilder zum Prüfen:

```bash
node schuss.mjs --t=19,38.6,57 --ordner=. --marke=probe
```

### Aufbau

```
motion/demo/
├── film.html        Bühne, Farben, Typografie
├── js/bausteine.js  Desktop, Fenster, Chat, Mini Jon, Katze, Zeiger
├── js/szenen.js     die elf Szenen als reine Funktion der Zeit
├── js/film.js       Regie: Zeitleiste, Blenden, Untertitel, Hochkant-Schnitt
├── js/vo.js         Untertitelzeiten (von ton.py geschrieben)
├── ton.py           Musik, Geräusche, Sprecher, Mischung
├── stimme.ps1       deutsche Windows-Stimme → WAV
├── render.mjs       Chrome → ffmpeg, Bild für Bild
└── schuss.mjs       Einzelbilder zum Prüfen
```

Jede Szene ist eine reine Funktion der Zeit: `seek(t)` liefert immer exakt
dasselbe Bild. Deshalb gibt es beim Export weder ausgelassene Bilder noch
Ruckeln, und beide Fassungen greifen auf denselben Aufbau zu — die
Kurzfassung ist nur ein anderer Kameraausschnitt derselben Szenen.
